## 1. `queue_linked_list.c`（真 Bug：`int` 函数返回 `NULL` 导致 C23/GCC 16 编译失败）

- **问题等级**：🔴 高（现代编译器直接编译失败 + 代码与注释自相矛盾）
- **问题位置**：第 194 行（`peek` 函数）与第 250 行（`dequeue` 函数）
- **原代码**：
  ```c
  int peek(Queue *queue, bool *status)
  {
    if (is_empty(queue))
    {
      *status = false;
      return NULL;
    }
    ...
  }

  int dequeue(Queue *queue, bool *status)
  {
    if (is_empty(queue))
    {
      *status = false;
      return NULL;
    }
    ...
  }
  ```
- **编译器表现**：在 GCC 16（默认 C23）下直接报错：
  `error: returning 'void *' from a function with return type 'int' makes integer from pointer without a cast [-Wint-conversion]`。
- **问题分析**：这两个函数已经通过 `bool *status` 传出是否成功，但空队列分支依然错误地写了 `return NULL;`（`NULL` 是 `(void *)0`，并非整型，即使第 186 行注释自己都说“不能用返回 NULL 来判断失败，因为它会等于 0”）。此外第 210 行 `enqueue()` 中 `malloc` 未检查是否返回 `NULL`。
- **修改建议**：
  1. 将第 194、250 行的 `return NULL;` 改为 `return 0;`（错误状态已由 `*status = false;` 标识）。
  2. `enqueue()` 中补充 `if (newNode == NULL) return;` 防空指针解引用。

## 2. `error.c`（故意 `#error` 演示未加条件隔离导致编译必中断）

- **问题等级**：🟡 中（教学故意触发编译报错）
- **问题位置**：第 21 行、第 29–30 行
- **原代码**：
  ```c
  #error ERROR MESSAGE GOES HERE!

  #if INT_MAX < 2147483648
    #error INT_MAX Not Large Enough!
  #endif
  ```
- **编译器表现**：`error: #error ERROR MESSAGE GOES HERE!` 与 `error: #error INT_MAX Not Large Enough!`。
- **问题分析**：本文件用于演示 `#error` 预处理指令如何主动中断编译，但两处 `#error` 都处于激活状态，在常见的 32 位 `int`（`INT_MAX = 2147483647`）平台必定无法编译通过。
- **修改建议**：保持 `#if INT_MAX < 2147483648` 作为原理演示或用 `#if 0` / 注释提示“取消注释观察 `#error` 如何阻断不满足平台假设的编译”。

## 3. `ifdef_ifndef.c`（`sizeof` 使用 `%lu` 格式符）

- **问题等级**：🟡 中（Windows 64 位下格式符类型不匹配）
- **问题位置**：第 60 行
- **原代码**：
  ```c
  printf("sizeof(buffer): %lu\n", sizeof(buffer));
  ```
- **编译器表现**：`gcc -Wall` 警告 `format '%lu' expects argument of type 'long unsigned int', but argument 2 has type 'long long unsigned int'`。
- **修改建议**：改为 `printf("sizeof(buffer): %zu\n", sizeof(buffer));`。
