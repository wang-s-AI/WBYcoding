# 第 7 阶段《多线程、时间测量与系统接口》待纠正文件清单

本目录存放从 `07_concurrency_timing_system` 筛选出的需要确认并修正的文件，暂未改动原代码。

---

## 1. `detached_threads.c`（C23 函数签名报错 + 多线程数据竞争隐患）

- **问题等级**：🔴 高（GCC 16 编译报错 + 并发数据竞争）
- **问题位置**：
  1. **第 30 行与第 78 行**：
     ```c
     void *logger()
     ...
     return_value = pthread_create(&thread, NULL, &logger, NULL);
     ```
     在 GCC 16（C23）中，空参数表 `()` 等价于 `(void)` 而不再是旧式未指定参数列表，因此 `&logger` 类型为 `void *(*)(void)`，与 `pthread_create` 要求的 `void *(*)(void *)` 不兼容，直接报 `error: passing argument 3 of 'pthread_create' from incompatible pointer type`！
  2. **第 25、49、95–105 行（并发问题）**：全局变量 `incidents` 在主线程修改、在分离线程 `logger` 读取，未使用 `pthread_mutex_t` 或原子变量保护（存在 Data Race）；另外 `fprintf(log_file, ...)` 未调用 `fflush(log_file)`，程序结束前可能缓冲未落盘。
- **修改建议**：
  1. 将第 30 行签名改为 `void *logger(void *arg)`（第 78 行可传 `logger` 或 `&logger`），第 31 行加 `(void)arg;` 消除未使用参数警告。
  2. 在注释或后续版本中提示：真实工程应给 `incidents` 加互斥锁（参考同阶段 `mutex/`），并在写入后 `fflush(log_file)`。

## 2. `time.h`（源码误命名为 `.h` 后缀 + `time_t` 格式警告 + 变量遮蔽 `strlen`）

- **问题等级**：🔴 高（严重后缀错误，可能遮蔽系统 `<time.h>`）
- **问题位置**：
  1. **文件名**：`time.h` 实质是一个包含 `#include <time.h>` 和 `int main(void)` 的完整 C 演示程序，而非头文件！若编译参数含 `-I.`，还可能让其他文件 `#include "time.h"` 或系统搜索出冲突。
  2. **第 22、79、80 行**：`printf("%ld\n", now);`（Windows 64 位下 `time_t` 为 `long long int` 8 字节，而 `%ld` 期望 4 字节 `long int`）。
  3. **第 91 行**：`int strlen = strftime(s,100,"%l %p", cur_time);`——局部变量命名与标准库 `<string.h>` 的 `strlen` 撞名（不规范习惯）；且 `%l` 在 Windows UCRT `strftime` 中可能不受支持（跨平台常用 `%I`）。
- **修改建议**：
  1. 确认后重命名为 `time_demo.c`。
  2. 输出 `time_t` 改为 `printf("%lld\n", (long long)now);`。
  3. 第 91 行变量名改为 `len`（避免叫 `strlen`），格式化串说明 Windows 与 Linux 差异（`%I` vs `%l`）。

## 3. `time_null.c`（Windows 64 位下 `time_t` 用 `%ld` 打印导致格式警告与截断）

- **问题等级**：🟡 中（跨平台类型位数差异）
- **问题位置**：第 37 行
- **原代码**：
  ```c
  time_t current_time = time(NULL);
  printf("%ld\n", current_time);
  ```
- **编译器表现**：`gcc -Wall` 警告 `format '%ld' expects argument of type 'long int', but argument 2 has type 'time_t' {aka 'long long int'}`。
- **修改建议**：改为 `printf("%lld\n", (long long)current_time);`。

## 4. `list_dir_contents.c`（使用了 Windows MinGW `dirent.h` 不支持的非标准字段）

- **问题等级**：🟠 中高（Linux/macOS 可编译，Windows MinGW 直接编译报错）
- **问题位置**：第 45、52 行
- **原代码**：
  ```c
  if (entry->d_type == DT_REG)
  ...
  else if (entry->d_type == DT_DIR)
  ```
- **编译器表现**：MinGW `ucrt64` 报错 `error: 'struct dirent' has no member named 'd_type'` 与 `'DT_REG' undeclared`。
- **问题分析**：`d_type` 并非 POSIX 强制标准字段，Windows MinGW 的 `<dirent.h>` 未提供它；可移植的 POSIX 写法是配合 `stat()` + `S_ISREG(st.st_mode)` / `S_ISDIR(st.st_mode)`，或标注仅限 Linux/macOS。
- **修改建议**：若需兼容 Windows MinGW 与 Linux，改用 `stat(entry->d_name, &st)` + `S_ISREG` / `S_ISDIR` 判断类型；或者保留作 Linux 专属示例并加平台注释。

## 5. `mkdir.c`（POSIX 2 参数 `mkdir` 在 Windows 下编译报错 + `extern int errno;` 冲突）

- **问题等级**：🟠 中高（Windows 下无法编译）
- **问题位置**：
  1. 第 19 行：`extern int errno;`（与 MinGW `<errno.h>` 的 `_errno` dllimport 冲突，发出 `-Wattributes` 警告）。
  2. 第 29 行：`mkdir("test1", S_IRWXU | S_IRWXG | S_IRWXO )`——在 Windows MinGW `<io.h>` 中 `mkdir` 只接收 1 个参数（同目录已有专门讲 Windows 版的 `_mkdir.c`），因此报错 `too many arguments to function 'mkdir'; expected 1, have 2`。
- **修改建议**：删除第 19 行手写的 `extern int errno;`；第 29 行通过 `#ifdef _WIN32` 区分 `_mkdir("test1")` 与 POSIX `mkdir("test1", 0777)`，或在注释中明确标注“此文件仅限 Linux/macOS，Windows 请看同目录 `_mkdir.c`”。

## 6. `errno.c`（手写 `extern int errno;` 与现代 `<errno.h>` 声明冲突）

- **问题等级**：🟢 低（编译警告 / 不规范旧写法）
- **问题位置**：第 18 行
- **原代码**：
  ```c
  #include <errno.h>
  ...
  extern int errno;
  ```
- **编译器表现**：`warning: '_errno' redeclared without dllimport attribute: previous dllimport ignored [-Wattributes]`。
- **问题分析**：现代多线程 C 库中 `errno` 通常是一个展开为函数调用的宏（如 `(*_errno())`），绝不应手动加 `extern int errno;`，只需 `#include <errno.h>` 即可。
- **修改建议**：直接删除第 18 行 `extern int errno;`（并加注释说明原因）。
