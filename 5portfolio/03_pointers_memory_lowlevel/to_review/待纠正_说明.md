## 1. `segmentation_fault.c`（真实语法笔误导致无法编译）

- **问题等级**：🔴 高（意外语法报错）
- **问题位置**：第 39 行
- **原代码**：
  ```c
  printf("%d\n", data[2];)
  ```
- **编译器表现**：`error: expected ')' before ';' token`，连带导致后面 `index` 作用域报错。
- **问题分析**：本文件旨在演示**运行时**段错误（越界访问、空指针、野指针、无限递归等），第 39 行明显是把分号 `;` 打进了圆括号里面，属于作者笔误。
- **修改建议**：改为 `printf("%d\n", data[2]);`。

## 2. `declare_multiple_pointers.c`（故意报错行未注释 + `sizeof` 格式符错误）

- **问题等级**：🟠 中高（无法直接编译 + 格式符不匹配）
- **问题位置**：

- **修改建议**：

  2. 将第 50、51、56、57 行的 `%d` 全部改为 `%zu`。

## 3. `lvalues_ravlues.c`（文件名拼写错误 + C89 废弃语法 + 故意报错未注释）

- **问题等级**：🟠 中高（拼写错误 + 现代 C 非法语法 + 无法编译）

- **修改建议**：
  1. 重命名为 `lvalues_rvalues.c`（确认后执行）。
  2. 第 43 行改为 `const int y = 20;`。
  3. 将第 35、44、48、53、60 行的错误演示语句注释或用 `#if 0` 隔离，方便逐条取消注释测试编译器报错信息。

## 4. `array_vs_&array.c`（指针直接用 `%zu` 打印导致大量格式警告）

- **问题等级**：🟡 中（标准 C 格式符不匹配 UB / GCC 产生 13 条警告）
- **问题位置**：第 36–37、48–49、66–68、82–84、96–97、103 行
- **原代码举例**：
  ```c
  printf("     array: %zu\n", array);
  printf(" *(matrix[1] + 1): %zu\n\n", *(matrix[1] + 1));
  ```
- **问题分析**：
  - 作者为了用十进制直观展示指针 `+ 1` 的字节偏移量（比 `%p` 十六进制好算），把 `int *`、`int (*)[5]` 指针直接传给 `%zu`；
  - 更严重的是第 68、97、103 行把解引用后的 `int` 值也用 `%zu` 打印！在 64 位 Windows 上 `int`（32 位有符号）与 `size_t`（64 位无符号）位数不同，属于未定义行为。
- **修改建议**：
  - 指针十进制地址：引入 `#include <stdint.h>`，写为 `printf("... %zu\n", (size_t)(uintptr_t)array);` 或保留 `%p` 加 `(void *)`。
  - 第 68、97、103 行的整数值改回 `%d`。

## 5. `realloc_vulnerability.c`（64位指针强转 32位 `int` 截断 + 标题拼写错误）

- **问题等级**：🟡 中（指针截断警告 + 标题拼写）
- **问题位置**：
  1. 第 3 行标题：`vulnernability` 拼写多了一个 `n`。
  2. 第 46、71、78 行：`printf("p1 addr: %d\n...", (int) password1, ...)`。
- **问题分析**：在 64 位系统上指针为 8 字节，强转为 32 位 `int` 会丢失高 32 位地址并触发 `-Wpointer-to-int-cast` 警告。此外第 51 行 `for (int i = 0; i < 100; i++)` 刻意越界读取堆内存演示残留密码（属于教学演示目的，但建议在注释中强调用 Valgrind/ASan 时会触发越界报警）。
- **修改建议**：
  - 第 46、71、78 行若要十进制输出地址，改为 `#include <stdint.h>` 后使用 `(uintptr_t)password1` 配合 `%zu`（或直接删掉该行，只保留上一行的 `%p`）。
  - 修正第 3 行注释拼写 `vulnerability`。
