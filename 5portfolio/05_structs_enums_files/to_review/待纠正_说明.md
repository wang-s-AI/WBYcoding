## 1. `binary/` 子目录（Windows 下大数组放栈上导致栈溢出崩溃）

- **问题等级**：🔴 高（Windows 下运行极易 Stack Overflow 闪退）
- **涉及文件**：
  - `binary/read_binary.c`（第 17 行：`int data[1000000];`）
  - `binary/write_binary.c`（第 17 行：`int data[1000000];`）
  - `binary/read_text.c`（第 18 行：`int data[1000000];`）
- **问题分析**：
  `int data[1000000]` 占用约 **4,000,000 字节（3.81 MB）** 栈空间。Linux 默认栈通常为 8 MB 可以跑过，但 Windows 下 MSVC 默认栈仅 1 MB、MinGW 默认栈仅 2 MB，直接运行会触发栈溢出异常退出（`0xC00000FD`）。此外 `binary/read_text.c` 中 `data` 赋值后从未使用，且未检查 `fgets` 返回值。
- **修改建议**：
  将 `int data[1000000];` 改为动态堆分配：
  ```c
  int *data = malloc(sizeof(int) * 1000000);
  if (data == NULL) return 1;
  // ... 注意 write_binary.c 中 fwrite(data, sizeof(int), 1000000, file);
  //     read_binary.c 中 fread(data, sizeof(int), 1000000, file);
  //     不能再用 sizeof(data)！因为 data 变成指针后 sizeof(data) 只有 8 字节！
  free(data);
  ```
  （特别注意：改为指针后必须同步把 `sizeof(data)` 改为 `sizeof(int) * 1000000`！）

## 2. `replace_line.c` & `write_specific.c`（使用未定义行为 `fflush(stdin)` + 未限制 `scanf("%s")`）

- **问题等级**：🟠 中高（标准 C 未定义行为 UB）
- **问题位置**：
  - `replace_line.c` 第 56 行：`fflush(stdin);`（及第 44 行无长度限制 `scanf("%s", filename)`）
  - `write_specific.c` 第 57 行：`fflush(stdin);`（及第 45 行无长度限制 `scanf("%s", filename)`）
- **问题分析**：C 标准规定 `fflush()` 仅定义用于输出/更新流，对输入流 `stdin` 调用属于**未定义行为（UB）**。在 Windows MSVC/UCRT 上有时碰巧能用，但换到 Linux/GCC 或 C++ 课堂环境就会失效，导致后面的 `fgets` 直接读到残留的 `\n` 而跳过输入！（仓库里 `04_strings_stdio/clear_input_buffer.c` 本身就专门讲过为什么不该用 `fflush(stdin)`）。
- **修改建议**：将 `fflush(stdin);` 替换为标准可移植的清空输入缓冲循环：
  ```c
  int ch;
  while ((ch = getchar()) != '\n' && ch != EOF) {}
  ```
  并将 `scanf("%s", filename)` 改为 `scanf("%1023s", filename)`（或改用 `fgets` 去换行）。

## 3. `clearerr.cpp`（纯 C 代码误命名为 `.cpp` 后缀）

- **问题等级**：🟡 中（文件扩展名错误 + 运行需提前存在 `file.txt`）
- **问题位置**：文件名 `clearerr.cpp`；第 25–26 行先以 `"r"` 打开再以 `"w"` 打开同一个 `file.txt`。
- **问题分析**：文件内容 100% 是 C 语言教程（`<stdio.h>`、`<stdbool.h>`），命名为 `.cpp` 会被 IDE/编译器按 C++ 编译。另外用 `"w"` 截断文件同时让另一个只读句柄 `file_read` 保持打开并依赖 OS 允许读写共享，在部分严格模式下也容易产生困惑。
- **修改建议**：确认后重命名为 `clearerr.c`。

## 4. `fprintf.c`（Windows 64 位 `unsigned long` 整数溢出截断）

- **问题等级**：🟡 中（Windows LLP64 模型下发生数据溢出）
- **问题位置**：第 135 行
- **原代码**：
  ```c
  unsigned long ul = 123456789012345;
  fprintf(file, "%lu\n", ul);
  ```
- **编译器表现**：`gcc -Wall` 警告 `unsigned conversion from 'long long int' to 'long unsigned int' changes value from '123456789012345' to '2249056121'`。
- **问题分析**：在 Linux 64 位（LP64）中 `unsigned long` 为 64 位，但在 Windows 64 位（LLP64）中 `unsigned long` 只有 32 位（最大 `4,294,967,295`），导致常量直接截断溢出！这也是跨平台开发（Windows vs Ubuntu）的经典坑。
- **修改建议**：若演示 `unsigned long` 可改用 32 位范围内的值（如 `4000000000UL`），或者改用 `unsigned long long` 配合 `%llu`。

## 5. `unions.c`（`sizeof` 使用 `%d` 格式符）

- **问题等级**：🟡 中（64 位下 `printf` 格式符类型不匹配）
- **问题位置**：第 79、80、86 行
- **原代码**：
  ```c
  printf("mydata size: %d\n", sizeof(mydata));
  printf("char size: %d\n", sizeof(char));
  printf("mydata2 size: %d\n", sizeof(mydata2));
  ```
- **修改建议**：将三处 `%d` 改为 `%zu`。
